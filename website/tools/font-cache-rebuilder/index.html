Frequently Asked Questions

Why does Windows display square boxes (□□□) or missing text glyphs? +
Windows caches rendered font glyph metrics in binary databases like FNTCACHE.DAT and FontCache3.0.0.0.dat to accelerate UI drawing. If a system update, sudden shutdown, or custom font installation corrupts these index tables, the Windows font rasterizer fails to match character codes to glyph vectors, rendering empty boxes or garbled symbols across your browser, Microsoft Office, and Windows desktop.
Why is fontdrvhost.exe consuming high CPU or memory in Task Manager? +
fontdrvhost.exe is the Windows User Mode Font Driver Host responsible for rendering complex OpenType and TrueType fonts in an isolated sandbox. When font cache indices become malformed, fontdrvhost enters recursive parsing loops attempting to rebuild glyph tables on every frame. Purging the corrupted cache databases terminates the loop and drops CPU usage back to 0%.
Can deleting font cache files harm my operating system? +
No. Font cache files are purely transient performance buffers. Deleting FNTCACHE.DAT and WPF cache files is completely safe because Windows automatically recreates clean, uncorrupted binary caches the moment the Windows Font Cache Service restarts.
Do I need to restart my computer after rebuilding the font cache? +
No. Pexoris FontCacheRebuilder broadcasts a native Win32 WM_FONTCHANGE message to all open top-level application windows and can optionally refresh Windows Explorer shell in place. Open applications will immediately redraw text using clean metrics without requiring a system reboot.
