Why Do Windows Shortcuts Break and Show Blank Icons?

In Windows, desktop and Start menu shortcuts are stored as binary shell link files with the .lnk extension. Each .lnk file contains hardcoded metadata, including:

  • Target Path: The absolute file path of the executable (e.g. C:\Program Files\App\App.exe).
  • Working Directory: The execution root folder.
  • Icon Location: A pointer to the icon resource embedded within the binary.

Because these paths are absolute, shortcuts break whenever:

  1. Software is moved to another drive: Moving apps from C: to D: to save SSD space leaves old shortcuts pointing to non-existent C: paths.
  2. Software updates change folder versions: Apps like Photoshop, Blender, or Python that install into versioned folders (e.g., Photoshop 2024 vs Photoshop 2025) orphan existing shortcuts.
  3. Incomplete uninstallations: Uninstallers frequently leave dead shortcuts on the Desktop and in AppData\Roaming\Microsoft\Windows\Start Menu\Programs.

When you double-click a broken shortcut, Windows freezes Explorer while searching network shares and drives trying to locate the file, eventually throwing the error: "The item referred to by this shortcut has been moved or deleted."

Method 1: Manual Fix via Shortcut Properties

If only one or two shortcuts are broken, you can manually re-link them:

  1. Right-click the broken desktop shortcut and select Properties.
  2. In the Shortcut tab, look at the Target field.
  3. Click Open File Location. If Windows cannot find it, click Browse... and navigate to the real executable path.
  4. Click Apply and OK. The icon will immediately restore from the target binary.

Method 2: Batch Scan Broken Shortcuts via PowerShell

To find all dead shortcuts across your Desktop using PowerShell without opening each one individually, run:

# PowerShell Script to Detect Broken Desktop Shortcuts
$wsh = New-Object -ComObject WScript.Shell
$desktop = [Environment]::GetFolderPath('Desktop')
Get-ChildItem -Path $desktop -Filter *.lnk | ForEach-Object {
    $sc = $wsh.CreateShortcut($_.FullName)
    if ($sc.TargetPath -and !(Test-Path $sc.TargetPath)) {
        Write-Host "BROKEN:" $_.Name "➔" $sc.TargetPath -ForegroundColor Red
    }
}

Method 3: How to Fix Blank White Icons (Icon Cache Refresh)

If the shortcut's target is healthy but the icon remains a blank white paper sheet, your Windows Icon Cache database is corrupted. You can purge the icon cache database using Command Prompt:

:: Terminate Windows Explorer
taskkill /F /IM explorer.exe

:: Delete Corrupted IconCache Database
del /A /F /Q "%LocalAppData%\IconCache.db"
del /A /F /Q "%LocalAppData%\Microsoft\Windows\Explorer\iconcache*"

:: Restart Explorer
start explorer.exe
