Why Does Windows Corrupt Font Caches & Show Square Boxes?

Windows renders millions of text characters per second across desktop windows, taskbars, browsers, and productivity apps. To avoid recalculating vector Bézier curves for every letter on every frame, the Windows DirectWrite and GDI subsystems cache pre-rasterized glyph metrics into binary files:

  • C:\Windows\System32\FNTCACHE.DAT — The primary system-wide GDI font cache.
  • C:\Windows\ServiceProfiles\LocalService\AppData\Local\FontCache\*.dat — System-level DirectWrite font tables.
  • FontCache3.0.0.0.dat — The Windows Presentation Foundation (WPF) glyph cache used by modern desktop software.

When Windows experiences an unexpected shutdown, a graphic driver update crash, or a corrupted font file installation, the internal binary indexes of these .dat files become malformed. As a result:

  1. Square Boxes (□□□) & Question Marks: The font engine cannot find the glyph metric in the cache, rendering the missing-glyph fallback symbol (the "tofu" rectangle).
  2. FontDrvHost.exe 100% CPU Spike: The User Mode Font Driver Host enters an infinite recursion loop trying to parse broken font headers.
  3. "File in Use" Lock Error: When you attempt to delete FNTCACHE.DAT manually, Windows blocks you because the background service has an active handle lock on the file.

Method 1: Manual Fix via Elevated Command Prompt (Native Windows)

If you prefer using native Windows terminal commands, you can stop the background font services, delete the cached tables, and trigger a regeneration cycle:

Step 1: Open Terminal as Administrator

Press Win + X and select Terminal (Admin) or search for cmd.exe, right-click, and choose Run as administrator.

Step 2: Stop Font Cache Services

Execute the following commands to disengage active file locks:

:: Stop the primary Windows Font Cache Service net stop fontcache :: Stop the WPF font cache service net stop FontCache3.0.0.0

Step 3: Delete Locked Cache Databases

Run these commands to delete corrupted system and user-profile font cache databases:

:: Delete legacy GDI font cache del /A /F /Q "%windir%\System32\FNTCACHE.DAT" :: Delete LocalService cache tables del /A /F /Q "%windir%\ServiceProfiles\LocalService\AppData\Local\FontCache\*.dat" del /A /F /Q "%windir%\ServiceProfiles\LocalService\AppData\Local\FontCache3.0.0.0.dat" :: Delete user-level font cache del /A /F /Q "%LocalAppData%\FontCache\*.dat"

Step 4: Restart Services & Refresh Windows Shell

Restart the service to recreate clean cache indices:

:: Restart font service net start fontcache :: Restart Windows Explorer to reload shell font metrics taskkill /F /IM explorer.exe & start explorer.exe
